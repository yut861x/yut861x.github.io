日常账本：架构与使用指南

发表于2026-10-09|更新于2026-10-09|实用工具
|浏览量:

我做了一个可以在手机和电脑上使用的日常账本：日常手动记一笔，固定收支按计划生成，付款截图也能通过 iPhone 快捷指令识别后确认入账。代码放在 GitHub。这篇文章先讲怎么用，再交代它的数据流与安全边界。

从哪里开始

打开日常账本，用邮箱注册或登录。若注册后需要验证邮箱，先完成邮件确认。登录后，侧栏可以进入总览、账目、分类统计、日历，也可以选择具体账本。

总览汇总所选月份的所有账本：本月收入、支出、结余，收入和支出的像素风分类饼图，以及最近记录。最近记录会标出所属账本。点击侧栏某一本账本，会进入该账本的账目；分类统计、日历和 CSV 导出仍以当前账本为范围。切换月份用页面上方的左右箭头。

账本与日常记账

账本分为四类，侧栏按“动态支出 → 固定支出 → 动态收入 → 固定收入”排列。支出账本与收入账本使用不同图标；新建账本时选好类别，新增账目会据此预选收入或支出，但保存前仍可手动切换。

类别 适合记录
动态支出 餐饮、购物、交通等随时发生的开销
固定支出 房租、订阅等周期性支出
动态收入 副业、红包、奖金等不固定收入
固定收入 工资等周期性收入

点“记一笔”，选择账本、收入或支出、金额、分类和日期，备注可留空。保存后可以在账目列表中编辑或删除。账目按所选日期计入对应月份；界面目前以人民币显示。

“固定”首先是账本分类，不会仅因选择固定类别就自动生成记录。自动计划目前适用于内置的工资账本与固定支出账本：进入对应账本，设置每月日期、北京时间、金额；固定支出还要填写用途。计划可以暂停或修改，设为 31 日时短月按当月最后一天执行。自动生成的账目仍可手动编辑。

用付款截图记账

iPhone 快捷指令可以从分享菜单接收付款截图，也可以配置“设置 → 无障碍 → 触控 → 轻点背面 → 轻点两下”来运行截图记账快捷指令。它先在手机上截图、提取文字，给出候选金额，再由你确认或修改金额、选择收支类型与分类，最后才提交。

截图里可能同时有原价、优惠金额和实付金额，OCR 也可能误读数字，因此一定要在确认页核对金额，不要把识别结果当成最终账目。完整动作顺序、请求字段和错误处理见快捷指令配置说明。

首次使用快捷指令，要先在网站侧栏的“快捷指令接入”生成专用密钥，并填入快捷指令的请求标头。密钥只显示一次；不要把它发给别人，也不要放进公开分享的快捷指令。若怀疑泄露，可在网站撤销或重新生成，旧密钥会立即失效。

架构：静态网页与云端数据分开

网页是 Vue 3 + Vite 构建的静态应用，由 GitHub Pages 托管；Pages 本身不存账目。用户登录走 Supabase Auth，账本、账目和自动计划保存在 Supabase Postgres。网页通过 Supabase API 读取和修改本人数据，数据库的行级安全策略（RLS）负责隔离不同用户，而不是依赖前端隐藏按钮。

截图记账走另一条入口：iPhone 快捷指令 → Supabase Edge Function → Postgres。截图和 OCR 原文留在手机上；接口只接收人工确认后的类型、金额、分类、日期、备注等字段。Edge Function 校验专用密钥、字段格式和账本归属后才新增账目。密钥不能用来查询、修改或删除记录。

内置固定收支计划由 Supabase Cron 按北京时间触发，写入对应账本；前端负责设置和展示计划。账目金额在数据库中使用两位小数的数值字段，日期使用日期字段，这样按月统计不受浏览器显示格式影响。

想自己部署

项目的 README 列出 Supabase 建表与迁移脚本、环境变量、本地运行和 GitHub Pages 部署步骤。前端只应使用 Supabase 的 publishable key；service_role 或其他 secret key 不能写进 VITE_ 变量、网页源码或公开仓库。长期使用建议定期备份数据库；应用内 CSV 导出只覆盖当前账本、当前月份及当前筛选结果。

这个工具的目标很朴素：让随手记账足够轻，让金额确认和数据边界足够明确。
